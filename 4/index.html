Project 04 · Part A & B

Image Warping, Mosaicing and Autostitching

Part A: Image Warping and Mosaicing

Overview

This part of the project is about projective warping. From a few clicked point correspondences I compute a homography between two images, use it to warp one image into the other's perspective with inverse warping, and apply this to two tasks: rectifying planar objects that were photographed at an angle, and stitching several photos into a mosaic. Everything except basic linear algebra (least squares, matrix inverse) and a distance transform for blending is implemented by hand with NumPy.

A.1: Shooting the pictures

For each mosaic I took three photos from one spot and only rotated the phone between them, with about 40–70% overlap and the main (1×) lens. A fixed center of projection is what makes the transformation between the photos a homography. All images were downscaled to about 1200 px on the long side before clicking correspondences.

A.2: Recovering homographies

A homography maps a point (x, y) to (x', y') via p' = H p in homogeneous coordinates. With the bottom-right entry fixed to 1, H has eight unknowns a–h: 

    | a  b  c |        x' = (a·x + b·y + c) / (g·x + h·y + 1)
H = | d  e  f |        y' = (d·x + e·y + f) / (g·x + h·y + 1)
    | g  h  1 |

Multiplying both equations by the denominator makes them linear in the unknowns. Every correspondence therefore gives two rows of a linear system A h = b: 

[x, y, 1, 0, 0, 0, −x·x', −y·x'] · h = x'
[0, 0, 0, x, y, 1, −x·y', −y·y'] · h = y'

With n points, A is 2n × 8. Four points determine H exactly; for the mosaics I clicked about ten points per pair, so the system is overdetermined and solved with least squares, which averages out small clicking errors. 

def computeH(im1_pts, im2_pts):
    A, b = [], []
    for (x, y), (xp, yp) in zip(im1_pts, im2_pts):
        A.append([x, y, 1, 0, 0, 0, -x * xp, -y * xp])
        A.append([0, 0, 0, x, y, 1, -x * yp, -y * yp])
        b.append(xp)
        b.append(yp)
    h = np.linalg.lstsq(np.asarray(A), np.asarray(b), rcond=None)[0]
    return np.append(h, 1).reshape(3, 3)

To check each homography, I mapped the clicked points of one image through H and measured the distance to their partners in the other image. For the final point sets this reprojection error is a few pixels per point (for example 1.8–5.5 px for facade a → b and below 4 px for both bookshelf pairs).

This check was essential. My first attempts at the facade and the Campanile produced wildly distorted mosaics, and the reasons were different. For the facade, several windows were miscounted, which showed up as errors of up to 116 px. For the Campanile, the error was small, but all points lay on the narrow tower, almost on one vertical line. H then fits perfectly along that line but is undetermined sideways, so the image tilted away. Re-clicking with points spread over the whole overlap, including branch tips left and right of the tower, fixed both.

A.3: Warping the images

Warping uses inverse mapping so that every output pixel gets exactly one value and there are no holes:

  1. Choose the output region (bounding box) in the target coordinates.
  2. Build a grid of all output pixel coordinates with np.meshgrid and stack them as homogeneous points (3 × N).
  3. Multiply with H⁻¹ and divide by the third coordinate to get the source position of every output pixel.
  4. Sample the source image at these (generally non-integer) positions.

The whole computation is vectorized with NumPy, without loops over pixels. The output has a fourth alpha channel that is 1 where the source position lies inside the original image and 0 elsewhere, so areas without data are transparent. 

def inverse_map(H, box):
    x_min, x_max, y_min, y_max = box
    X, Y = np.meshgrid(np.arange(x_min, x_max + 1), np.arange(y_min, y_max + 1))
    stack = np.stack([X.ravel(), Y.ravel(), np.ones(X.size)])
    src = np.linalg.inv(H) @ stack
    src_x = (src[0] / src[2]).reshape(X.shape)
    src_y = (src[1] / src[2]).reshape(X.shape)
    return src_x, src_y

By default the bounding box comes from sending the four image corners through H. For the rectifications this fails: the TV was photographed so obliquely that the vanishing point of its top and bottom edges lies inside the photo. Everything beyond that line has no valid position on the TV plane (the homogeneous coordinate w changes sign), and those corners land at absurd coordinates. For rectification I therefore use a fixed output box around the target rectangle with 200 px margin.

Nearest neighbor and bilinear interpolation

Nearest neighbor rounds the source position to the closest pixel. Bilinear takes the four surrounding pixels and blends them, weighted by the fractional distances dx and dy: 

value = (1−dx)(1−dy)·I[y0, x0] + dx(1−dy)·I[y0, x1]
      + (1−dx)dy·I[y1, x0]     + dx·dy·I[y1, x1]

I use the convention that integer coordinates are pixel centers, which is also how matplotlib displays images and reports clicked points.

Rectification

For rectification there is only one image. I clicked the four corners of a rectangular object and mapped them to a rectangle with the object's real aspect ratio: 16:9 (1280 × 720) for the TV screen, and about 25 × 12 cm (1250 × 600) for the laptop keyboard, measured roughly.

Bilinear interpolation is about four times slower, since it reads four source pixels instead of one and computes the weights. In return, it gives smoother results: nearest neighbor produces jagged, staircase-like edges, which are most visible on text and diagonal lines such as the lettering on the TV screen and the key labels. Bilinear looks slightly softer but has no such artifacts. For the mosaics I use bilinear.

A.4: Blending the images into a mosaic

The procedure for each mosaic:

  1. The middle image b is the reference. I compute H_ab (a → b) and H_cb (c → b; the b ↔ c points are passed in swapped order). Image b itself uses the identity matrix, so the same warp function works for all three images.
  2. The bounding boxes of all three warped images are combined into one common output box.
  3. All three images are warped with bilinear interpolation into this same box, so they are stacked on top of each other with identical size.
  4. The stack is blended into one image.

The simplest blending is an average of all images that have alpha = 1 at a pixel. This produces visible edges wherever an image starts or ends. For feathering, each image instead gets a weight equal to the distance of each pixel to the border of that image (scipy.ndimage.distance_transform_edt of its alpha channel). Every image fades out smoothly towards its edges, and the result is the weighted average: 

weight_a = distance_transform_edt(warped_a[..., 3])[..., None]
...
result = (rgb_a * weight_a + rgb_b * weight_b + rgb_c * weight_c) \
         / (weight_a + weight_b + weight_c)

With the simple average, the outline of the reference image is clearly visible as a brighter rectangle in the middle. Feathering removes these hard edges.

What I learned (Part A)

The math of a homography is short, but the result depends almost entirely on the correspondences. Points that are wrong by one window, or points that are accurate but all lie on one line, both break the mosaic, and only the second case is invisible in the reprojection error. Spreading the points over the whole overlap mattered more than clicking more of them. I also learned where a homography stops being meaningful: beyond the vanishing line of a plane, points have no valid image, which is why the bounding box from the image corners failed for the strongly tilted TV.

Part B: Feature Matching for Autostitching

Overview

In Part A every correspondence was clicked by hand. In Part B the whole pipeline runs automatically, following the paper "Multi-Image Matching using Multi-Scale Oriented Patches" by Brown, Szeliski and Winder (in a simplified single-scale version). For each image pair I detect corners, pick a well-distributed subset, describe each corner with a small normalized patch, match the patches between the two images, and finally estimate the homography robustly with RANSAC. The warping and blending code is the same as in Part A. The examples in B.1 to B.3 use the bookshelf set (mosaic 3), images a and b.

B.1: Harris corner detection

Corners are detected with the single-scale Harris detector from the provided harris.py on the grayscale image. Each pixel gets a corner strength h, and local maxima are kept as interest points. I additionally discard all corners closer than 20 px to the image border, because the 40 × 40 descriptor window in B.2 would otherwise reach outside the image.

Harris returns thousands of corners, and most of them sit in highly textured regions. To get a smaller set that is still spread over the whole image, I use Adaptive Non-Maximal Suppression (ANMS). For every corner i I compute its suppression radius: the distance to the nearest corner that is clearly stronger, 

r_i = min_j ‖x_i − x_j‖   over all j with  f(x_i) < c_robust · f(x_j),   c_robust = 0.9

and keep the 500 corners with the largest radius. A strong corner far away from other strong corners gets a large radius, so the selected points are both strong and evenly distributed. The computation is fully vectorized: one pairwise distance matrix, masked with the strength condition, then a minimum per row. 

def anms(h, corners, n=500, c_robust=0.9):
    f = h[corners[0], corners[1]]
    M = len(f)
    d = har.dist2(corners.T, corners.T)
    cond = f.reshape(M, 1) < c_robust * f.reshape(1, M)
    d = np.where(cond, d, np.inf)
    r = d.min(axis=1)
    return corners[:, np.argsort(-r)[:n]]

Harris returns several thousand corners that cover almost the entire image, including weakly textured areas like the floor and the ceiling, so the plot on the left is nearly solid blue. After ANMS, 500 corners remain and they are spread evenly over the whole image: on the book spines and labels, along the shelf edges, but also on the floor, wall and ceiling. Some of the points in low-texture regions will not be distinctive enough to match, but the ratio test in B.3 filters most of them out.

B.2: Feature descriptor extraction

For each selected corner I extract an axis-aligned 8 × 8 descriptor:

  1. Blur the grayscale image with a Gaussian (σ = 2), so that the subsampling in the next step does not alias.
  2. Take the 40 × 40 window around the corner and sample every 5th pixel, which gives 8 × 8 values.
  3. Bias/gain normalization: subtract the mean and divide by the standard deviation of the patch. This makes the descriptor invariant to brightness and contrast changes between the photos.
blurred = gaussian_filter(image_bw, 2)
patch = blurred[r - 20:r + 20:5, c - 20:c + 20:5]
patch = (patch - patch.mean()) / (patch.std() + 1e-8)

Rotation invariance and the wavelet transform from the paper are not needed here, since the photos of one mosaic were taken with the same camera orientation.

B.3: Feature matching

Each descriptor is flattened to a 64-dimensional vector. For every feature in image a I compute the squared distance (SSD) to every feature in image b and look at its nearest (1-NN) and second-nearest (2-NN) neighbor. A single nearest-neighbor distance is a poor criterion, because repeated structures (windows, book spines) produce many similar patches. Following Lowe, I instead use the ratio of the two: 

accept match  ⇔  e_1-NN / e_2-NN < 0.65

A correct match should be clearly better than the second-best candidate, while for an incorrect match both candidates are about equally bad. Since dist2 returns squared distances, the threshold of 0.65 corresponds to a ratio of about 0.81 on plain Euclidean distances.

Of the 500 features in image a, 110 pass the ratio test. Most of them lie on book spines, labels and shelf edges, where the patches are distinctive. Some matches are clearly wrong, for example points on the wall at the left edge of image a, a region that is not visible in image b at all. RANSAC later keeps 58 of the 110 matches, so roughly half of them were outliers. This is why the ratio test alone is not enough.

B.4: RANSAC for robust homography estimation

Even after the ratio test, some matches are wrong. A least-squares homography over all matches would be pulled away by these outliers, so I use 4-point RANSAC, implemented from scratch:

  1. Pick 4 random matches and compute the exact homography H from them (computeH from Part A).
  2. Map all points of the first image through H (homogeneous coordinates, divide by w) and measure the distance to their matched points.
  3. Matches with an error below ε = 3 px are inliers.
  4. Repeat 20 000 times and keep the largest inlier set.
  5. Recompute H with least squares on all inliers of the best set.
def ransac(pts1, pts2, n_iter=20000, eps=3):
    best_count, best_mask = -np.inf, None
    pts1_h = np.column_stack((pts1, np.ones(len(pts1))))
    for _ in range(n_iter):
        idx = np.random.choice(len(pts1), 4, replace=False)
        H = computeH(pts1[idx], pts2[idx])
        p = H @ pts1_h.T
        proj = np.column_stack((p[0] / p[2], p[1] / p[2]))
        inliers = np.linalg.norm(proj - pts2, axis=1) < eps
        if inliers.sum() > best_count:
            best_count, best_mask = inliers.sum(), inliers
    return computeH(pts1[best_mask], pts2[best_mask]), best_mask

The number of iterations matters more than I expected. RANSAC only finds the right model if all 4 sampled matches are inliers, which happens with probability w4 for an inlier ratio w. To succeed with probability p, it needs 

N = log(1 − p) / log(1 − w⁴)

iterations. My first version used 2000 iterations. For the bookshelf pair c ↔ b, only 8 of 60 matches were found as inliers, and the mosaic showed doubled, shifted shelves on the right. With w ≈ 0.13, a single sample is all-inlier with probability of only about 3 · 10⁻⁴, so 2000 iterations hit a correct sample less than once on average; for p = 0.99 about 15 000 are needed. With 20 000 iterations, RANSAC found 13 inliers and the mosaic was correct. Since each iteration is only a tiny 8 × 8 least-squares problem, this costs just a few seconds.

One detail: the corners are stored as (row, col), while computeH expects (x, y) = (col, row), so the coordinates are swapped before RANSAC.

The mosaics are built exactly as in Part A: b is the reference, a → b and c → b are estimated independently (each with its own matching and RANSAC), and all three images are warped into one common box and blended with feathering.

Mosaic 1: Glass facade — manual vs. automatic

The facade was the hardest set for automatic matching. Its regular grid of identical glass panels and vertical fins produces many patches that look almost the same, so the ratio test rejects most candidates and only 12 of 55 matches for a ↔ b survive RANSAC. Still, the facade continues without visible breaks in the automatic mosaic. The outer shape differs from the manual version: image a is stretched further to the left. Both homographies agree in the overlap, but small differences in H grow quickly towards the far edge of the warped image.

Mosaic 2: Campanile — manual vs. automatic

The Campanile worked best: 67 and 113 inliers, by far the most of all pairs. Tree branches, bricks and the stone of the planter give a lot of distinctive texture. The automatic mosaic is practically identical to the manual one. Unlike my first manual attempt, where all points lay on the tower, the automatic features are spread over the whole overlap, so this failure case cannot happen here.

Mosaic 3: Library bookshelf — manual vs. automatic

For a ↔ b the bookshelf was easy (58 inliers), but c ↔ b was difficult: image c is dominated by long rows of identical book sets, whose spines are indistinguishable at 8 × 8 resolution. Only 60 matches pass the ratio test and only 13 of them are inliers. With 2000 RANSAC iterations this pair failed (see B.4); with 20 000 iterations the automatic mosaic is as good as the manual one, and the shelf boards run straight across all three images.

Automatic mosaics

What I learned (Part B)

Automatic matching does not need perfect features, it needs a robust estimator. Half of the matches that pass the ratio test can be wrong, and RANSAC still finds the right homography, but only if it runs long enough: with a low inlier ratio, the required number of iterations grows with w−4, and too few iterations failed silently. I also saw that the scenes that are easiest to click by hand (regular facades, rows of identical books) are the hardest for patch descriptors, because repeated structures make the nearest neighbor ambiguous.
